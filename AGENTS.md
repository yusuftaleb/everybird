# Everybird: agent instructions

Everybird turns any birder's life list into a sticker collage. Import an eBird export or an iNaturalist username, or tick birds by hand; filter, edit and share. The list stays in the browser. It uses Yusuf's personal-site design system, and its collage page mirrors his /lifelist. Pages: Collage `/`, Settings `/settings`, About `/about`, shared view `/s/[token]`. Read these before any work:

- **Design system:** `DESIGN.md` (tokens, type, components, motion, voice, accessibility; sidecar `.impeccable/design.json`, product context in `PRODUCT.md`). Match it, and match `/lifelist`, for any UI work.
- **Spec (approved by Yusuf, 2026-11-05):** `docs/superpowers/specs/2026-11-05-everybird-design.md`, with "Changes after approval" at its end.
- **Plan (25 tasks):** `docs/superpowers/plans/2026-11-05-everybird.md`
- **Validation:** `docs/validation.md` (launch checklist; aggregates only, no personal data).

## Rules

- **Never commit personal data.** `private/` holds Yusuf's real eBird exports and his `lifelist.json`, and it's git-ignored. Test fixtures must be synthetic. Never commit coordinates, checklist comments or anything copied from those files.
- **Credit the stickers** wherever they appear, including share images: "Stickers: huashu-bird-sticker, CC BY 4.0", linking https://github.com/alchaincyf/huashu-bird-sticker.
- **Never commit the font files** for Satoshi and Cabinet Grotesk. Load them from Fontshare's CSS.

- **Ask Yusuf first, every time,** before anything outward-facing: creating GitHub repos, pushing, enabling GitHub Pages, creating or deploying the Vercel project, or posting anything. That's plan Task 25.
- **Keep this file current** as commands and structure change.

## Commands

- **Ports:** 3000 and 3001 are Yusuf's own dev servers: never start, stop or reuse them. Tests use 3100 (e2e dev), 3200 (e2e prod build) and 4100 (sticker server).
- `npm run dev`: Next dev server (port 3000, Yusuf's; pass `-p` to run another)
- `npm test`: Vitest unit tests (`tests/**/*.test.{ts,tsx}`; `tests/app-routes.test.tsx` runs / (Collage) and /settings under one provider and the top bar, with a mocked `next/navigation` and `next/link`; node by default, add `// @vitest-environment jsdom` for component tests). `tests/pack.test.ts` packs 5,000-bird lists on all three layouts (about 20 s); `SKIP_PERF=1` skips only the timing bounds
- `npm run e2e`: Playwright specs in `e2e/`. Playwright starts three servers: the sticker server on `127.0.0.1:4100`; `next dev` on port 3100 for the `chromium` project, the `webkit` project (`flows.spec.ts`, `timeline.spec.ts`, `share.spec.ts` and `settings.spec.ts` (one page head on Collage, Settings and About; Tick by hand's disclosure; remembered sources) in Safari's engine) and the `firefox` project (`flows`, `timeline`, `places`, `share`, `share-link`, `settings`, `about` and `smoke` specs in Gecko; install the engine once with `npx playwright install firefox`); and for the `perf` project (`filters.spec.ts`, the 4× frame-timing tests (filtering, and a held timeline drag over 1,000 species), serial, run alone after the others) a production build, `next build && next start -p 3200`. Both Next servers get `NEXT_PUBLIC_STICKER_BASE=http://127.0.0.1:4100`. Each Next server has its own dist dir (`NEXT_DIST_DIR=.next-e2e-dev` for dev, `.next-e2e` for the build; read in `next.config.ts`, both git-ignored), so they run beside your own `next dev` or `next start` on this checkout without touching its `.next`. Run the perf test alone with `npx playwright test --project=perf --no-deps`; every run rebuilds first (about 10–60 s), and all three servers start even for one project. A server already listening on 3100, 3200 or 4100 is reused as is, so stop a stale one first. Editing `next.config.ts` or `tsconfig.json` makes a running `next dev` restart itself. `BASE_URL=<url>` tests a deployed site instead, with no local servers. `e2e/flows.spec.ts` is the flow matrix, run by all three engines: each way in (eBird life list, MyEBirdData merged into it, iNaturalist through a mocked API, tick by hand), the filters (taxonomy, Places with two countries, a Time range and a trip), True size and the list view, the card (marks, remove, undo), the share image in all three formats with downloads, Copy link (Chromium's real clipboard; a stand-in recording the write elsewhere) and the shared view it opens, backup, forget and restore, and a check that no page scrolls sideways and every control takes a 44px press. By default each engine samples two widths (Chromium 390 and 1280, WebKit 390 and 1024, Firefox 768 and 1440: all five between them); the full matrix, every width in every engine, is `MATRIX=full npx playwright test e2e/flows.spec.ts --project=chromium --project=webkit --project=firefox`. `SHARE_PNG_DIR=<dir>` makes `e2e/share.spec.ts` save the story, post and square PNGs it downloads there (keep it outside the repo).
- `npm run e2e:stress`: the opt-in viral-scale suite (`e2e/stress.spec.ts`; its projects `stress-chromium` and `stress-webkit` exist only with `STRESS=1`): synthetic lists of 3,000, 6,000 and every species (~11,000) at 390 and 1440 px on the production build (port 3200), one at a time. Asserts no overlapping silhouettes and no sticker outside the stage (rasterised from the rendered page and the masks), the worker's first full layout under 20 / 40 / 90 s, deferred sticker downloads (only those within a screen of the viewport) and a JS heap under 400 MB (Chromium); logs `[stress]` lines with the scroll and filter frame timings at 4× CPU (Chromium), asserted only with `STRESS_STRICT=1`. About 10–20 minutes.
- `npm run stickers:serve`: serves `../everybird-stickers` (or `$STICKERS_DIR`) with CORS on `127.0.0.1:4100` only (or `$PORT`), for dev: run it next to `NEXT_PUBLIC_STICKER_BASE=http://127.0.0.1:4100 npm run dev`. Without the variable the app loads stickers from `https://yusuftaleb.github.io/everybird-stickers` (not live until Task 25). Script: `scripts/dev/serve-stickers.mjs`.
- Data pipeline (`scripts/build-data/`), in order: `npx tsx scripts/build-data/fetch-sources.ts` (downloads the eBird taxonomy, huashu, Natural Earth and iso-codes into the git-ignored `data/raw/`, writes `data/raw/manifest.json`), then `npm run data` = `copy-synonyms` → `build-species` → `build-geo` → `build-stickers` → `link-index`. Needs `data/raw/` and `../everybird-stickers` (or `STICKERS_OUT`). Then `npx tsx scripts/build-data/check-stickers.ts` (decodes every webp with sharp, lists failures and codes missing a size; exit 1 if any).
- `build-geo.ts` (writes `regions.v1.json`; there is no map): `REGION_RENAMES` (English names for inverted or bracketed ISO names, applied after the Natural Earth + ISO merge). `src/lib/import/inat.ts` `SUB1_ALIASES` keeps the local names matching iNaturalist places.
- `data/inat-synonyms.json` (iNaturalist sci name to eBird code, reasons in `inat-synonyms.notes.md`): `npm run data` publishes it via `scripts/build-data/copy-synonyms.ts` to `public/data/inat-synonyms.v1.json`.
- `npx tsx scripts/build-data/build-stickers.ts [--force | --codes a,b]`: trimmed 128/384 webp stickers into `${STICKERS_OUT:-../everybird-stickers}/v1/` (a separate git repo, never pushed from here), masks into `public/data/masks/<Order>.v1.json`, and the `ar` values in `species.v1.json`. Resumable: skips codes whose two webp files exist (`--force` regenerates all, `--codes` only those). **Run it after `build-species`** (`npm run data` does). build-species carries existing `ar` over by code, but species new to the file keep `ar: 1` until build-stickers runs.
- `npx tsx scripts/build-data/build-sample-pack.ts`: rebuilds `public/data/sample-pack.v1.json`, the landing sample packed ahead of time (the sample, the species rows and region names it uses, and its full even collage per layout class, packed by the layout worker's own handler with `public/data/masks`). Rerun after `build-sample.ts` or `npm run data`; `tests/sample-pack.test.ts` fails when the pack and the data disagree.
- `npx tsx scripts/build-data/build-sample.ts <framer-site/content/lifelist/lifelist.json>` (the path is required): rebuilds `public/data/sample.v1.json` (the landing demo) from the PUBLIC website list `framer-site/content/lifelist/lifelist.json`, keeping only code, YYYY-MM and `{country, sub1}`. Never point it at `private/`. Not part of `npm run data`. Yusuf approves the file before launch.
- `npx tsx scripts/validate/yusuf.ts [--offline]`: validation against Yusuf's own data (Task 24). Reads `private/` (his eBird files and `lifelist.json`), fetches iNaturalist `yusuftaleb` live at 1 request/s and saves the raw pages to `private/inat-yusuftaleb.json` (`--offline` replays them), merges with the default rules and diffs by code. Writes the species-level report to `private/validation-report.md` and prints one summary line. Only aggregates go in the committed `docs/validation.md`.
- `npx tsx scripts/build-data/build-flags.ts`: regenerates `src/lib/flag-urls.ts` (one static import per flag-icons 4x3 SVG with a two-letter code; Next serves them from this origin). Rerun after updating `flag-icons`.
- `npm run lint`, `npm run build`
- Moving or removing a route leaves the other dist dirs' generated `types/validator.ts` pointing at the old files. `tsconfig.json` excludes `.next-e2e` and `.next-e2e-dev`, so a stale e2e dir can't break `npm run build`; `.next/types` is still included, so after a route change the e2e build (`NEXT_DIST_DIR=.next-e2e`) fails its type check until `.next` is rebuilt: run `npm run build` once (or delete the stale `.next/types`). The e2e builds also rewrite the git-ignored `next-env.d.ts` to point at `.next-e2e`; your own `next dev` restores it.
