- **Ask Yusuf first, every time,** before anything outward-facing: creating GitHub repos, pushing, enabling GitHub Pages, creating or deploying the Vercel project, or posting anything. That's plan Task 25.

## Commands

- `npm run dev`: Next dev server (port 3000)
- `npm test`: Vitest unit tests (`tests/**/*.test.{ts,tsx}`; `tests/app-routes.test.tsx` runs /, /make and /my under one provider with a mocked `next/navigation` and `next/link`; node by default, add `// @vitest-environment jsdom` for component tests). `tests/pack.test.ts` packs 5,000-bird lists on all three layouts (about 20 s); `SKIP_PERF=1` skips only the timing bounds
- `npm run e2e`: Playwright specs in `e2e/`. Playwright starts three servers: the sticker server on `127.0.0.1:4100`; `next dev` on port 3100 for the `chromium` project; and for the `perf` project (`filters.spec.ts`, the 4× frame-timing test, run alone after the others) a production build, `next build && next start -p 3200`. Both Next servers get `NEXT_PUBLIC_STICKER_BASE=http://127.0.0.1:4100`. Each Next server has its own dist dir (`NEXT_DIST_DIR=.next-e2e-dev` for dev, `.next-e2e` for the build; read in `next.config.ts`, both git-ignored), so they run beside your own `next dev` or `next start` on this checkout without touching its `.next`. Run the perf test alone with `npx playwright test --project=perf --no-deps`; every run rebuilds first (about 10–60 s), and all three servers start even for one project. A server already listening on 3100, 3200 or 4100 is reused as is, so stop a stale one first. Editing `next.config.ts` or `tsconfig.json` makes a running `next dev` restart itself. `BASE_URL=<url>` tests a deployed site instead, with no local servers. `SHARE_PNG_DIR=<dir>` makes `e2e/share.spec.ts` save the story and post PNGs it downloads there (keep it outside the repo).
- `npm run stickers:serve`: serves `../everybird-stickers` (or `$STICKERS_DIR`) with CORS on `127.0.0.1:4100` only (or `$PORT`), for dev: run it next to `NEXT_PUBLIC_STICKER_BASE=http://127.0.0.1:4100 npm run dev`. Without the variable the app loads stickers from `https://yusuftaleb.github.io/everybird-stickers` (not live until Task 25). Script: `scripts/dev/serve-stickers.mjs`.
- Data pipeline (`scripts/build-data/`), in order: `npx tsx scripts/build-data/fetch-sources.ts` (downloads the eBird taxonomy, huashu, Natural Earth and iso-codes into the git-ignored `data/raw/`, writes `data/raw/manifest.json`), then `npm run data` = `copy-synonyms` → `build-species` → `build-geo` → `build-stickers` → `link-index`. Needs `data/raw/` and `../everybird-stickers` (or `STICKERS_OUT`). Then `npx tsx scripts/build-data/check-stickers.ts` (decodes every webp with sharp, lists failures and codes missing a size; exit 1 if any).
- `build-geo.ts`: `REGION_RENAMES` (English names for inverted or bracketed ISO names, applied after the Natural Earth + ISO merge). `src/lib/import/inat.ts` `SUB1_ALIASES` keeps the local names matching iNaturalist places.
- `data/inat-synonyms.json` (iNaturalist sci name to eBird code, reasons in `inat-synonyms.notes.md`): `npm run data` publishes it via `scripts/build-data/copy-synonyms.ts` to `public/data/inat-synonyms.v1.json`.
- `npx tsx scripts/build-data/build-stickers.ts [--force | --codes a,b]`: trimmed 128/384 webp stickers into `${STICKERS_OUT:-../everybird-stickers}/v1/` (a separate git repo, never pushed from here), masks into `public/data/masks/<Order>.v1.json`, and the `ar` values in `species.v1.json`. Resumable: skips codes whose two webp files exist (`--force` regenerates all, `--codes` only those). **Run it after `build-species`** (`npm run data` does). build-species carries existing `ar` over by code, but species new to the file keep `ar: 1` until build-stickers runs.
- `npx tsx scripts/build-data/build-sample.ts <framer-site/content/lifelist/lifelist.json>` (the path is required): rebuilds `public/data/sample.v1.json` (the landing demo) from the PUBLIC website list `framer-site/content/lifelist/lifelist.json`, keeping only code, YYYY-MM and `{country, sub1}`. Never point it at `private/`. Not part of `npm run data`. Yusuf approves the file before launch.
- `npx tsx scripts/validate/yusuf.ts [--offline]`: validation against Yusuf's own data (Task 24). Reads `private/` (his eBird files and `lifelist.json`), fetches iNaturalist `yusuftaleb` live at 1 request/s and saves the raw pages to `private/inat-yusuftaleb.json` (`--offline` replays them), merges with the default rules and diffs by code. Writes the species-level report to `private/validation-report.md` and prints one summary line. Only aggregates go in the committed `docs/validation.md`.
- `npm run lint`, `npm run build`
- Moving or removing a route leaves the other dist dirs' generated `types/validator.ts` pointing at the old files (`tsconfig.json` includes `.next/types`, `.next-e2e/types` and `.next-e2e-dev/types`), and any `next build` then fails its type check until that dir is rebuilt: run `npm run build` once (or delete the stale `<dist>/types`). The e2e builds also rewrite the git-ignored `next-env.d.ts` to point at `.next-e2e`; your own `next dev` restores it.

## Structure

- `app/`: Next.js app router (layout, pages). Imports styles via `@/styles/...`.
- Routes: `app/(app)/layout.tsx` wraps `/` (`app/(app)/page.tsx` → `Landing`), `/make` (`MakePage`), `/my` (`MyPage`) and `/credits` in `EverybirdProvider` (`src/components/app/EverybirdProvider.tsx`: the store from `useEverybird`, regions, the country dots and `use-import-jobs.ts`, the imports in flight), so they share one saved list and an import started on `/make` keeps running, with its progress, while the birder moves between them. `/s/[token]` sits outside the group and never loads or touches the saved list. The picked search bird is scrolled to once the unsearched layout is in (its new box), with a late correction after the travel. `Landing`: hero, the live `SampleDemo`, "Make yours" (→ /make) and, with a saved list, "Open my collage" (→ /my). `MakePage`: `PageHead`, the three ways in (`ImportPanel`), the privacy line, "See my collage" after an import (`data-testid="see-collage"`), restore (without a list), `MatchReport` and `RulesSwitches`. `MyPage`: Share and the downloads in the page head, `CollageView` with `EditBird` in the card, restore and forget; without a list it `router.replace`s to /make. `Notices.tsx` (memory-only, load failure, failed forget). `src/components/app/`: `CollageView` (stats line, `ControlsBar` (LifeList's dock: Collage/List tabs with the site's icons from `collage/icons.tsx`, the search, True size in collage view or "Heaviest first"/"Lightest first" in list view, Scientific), `CollageSearch` (the combobox: suggestions from the current list via `suggestBirds`, the text narrows the view as `Filter.q` after 140 ms; picking clears it, rings the bird or row with `data-ring` and opens its card, which follows the travelling bird), filters, collage or list, legend, card; shared by the landing demo, `/my` and the shared view), `use-collage-layout.ts` (one layout client per mounted collage, layout class from width, idle prefetch (none while searching); `setList` only when the codes or masses change, `refilter` when only dates, places or trips change, nothing for mark edits), `RestoreBackup`, `ThemeToggle` (in `SiteFooter`), `SiteFooter` (sticker credit, the /credits link and the theme switch, on every page). Scientific names (`AppState.sci`, never stored) lead in the card, list rows, search suggestions, order/family chips and the breadcrumb, as LifeList's `sci` does. `src/components/import/`: `ImportPanel` (the three ways in), `EbirdDrop` and `InatForm` (views of the jobs in `use-import-jobs.ts`; EbirdDrop says what each eBird file brings), `AddBirds`, `MatchReport`, `RulesSwitches`, `SpeciesSearch`. `src/components/edit/EditBird.tsx` (marks and remove, in the bird card). `src/components/share/ShareDialog.tsx` (lazy-loaded from `MyPage`'s Share button: story/post preview, Share image, Download image, Copy link, the name in `Saved.name`; `src/lib/share/make-link.ts` (`makeShareLink`: leaves out codes missing from the link index) with `link.ts` and its link index is a separate chunk fetched when the dialog opens; Copy link hands the clipboard a promised `ClipboardItem` inside the click where supported, else `writeText`, else a manual field; Share image and Download are disabled while the image renders). `src/lib/share/image.ts`: the share image (`cardLayout`, `renderShareImage`, token colours, `filterLabel`); it packs in a short-lived layout worker via the worker's `image` message (`packFrame` in `pack.ts`: no centre hole, sizes over the drawn birds).
- `app/(app)/credits/page.tsx` (+ `credits.css`): static credits page, inside the `(app)` group so following Credits from /make keeps an import in flight (it uses the group footer); reads `ebirdTaxonomy` and `huashuCommit` from `public/data/species.v1.json` at build time.
- Analytics: `src/lib/analytics.ts` `track()` wraps `@vercel/analytics` with the only three events (`collage_made {source}`, `image_downloaded {format}`, `link_copied {level}`; never counts, names or places). `src/components/app/SiteAnalytics.tsx` (`<Analytics beforeSend={redactAnalyticsEvent}>`: `/s/<token>` becomes `/s/[token]` in every page view and event URL; the layout also sets `referrer: strict-origin`) renders from `app/layout.tsx` only when `process.env.VERCEL` is set, so dev, tests and local builds load nothing and `track()` is a no-op.
- Link previews: `app/s/[token]/opengraph-image.tsx` (and `twitter-image.tsx`, a re-export) draws a 1200×630 card: at most 60 birds that have stickers (`pickOgStickers`: `st` only, then `pickOgBirds`, even steps through taxonomic order) packed with the wide layout into 640×560, the count at 120px and the latest lifer. `src/lib/share/og.ts` (pure: picking, title/description, `tryDecodeShare`), `og-server.ts` (species and masks via fs, fonts from Fontshare/Google cached in memory, stickers fetched with timeouts, converted to PNG with sharp because satori can't draw WebP, failures left out). `generateMetadata` in `app/s/[token]/page.tsx`: title "<name>'s Everybird — <n> species" ("An Everybird" without a name). `src/lib/sticker-url.ts` holds `stickerUrl` (server-safe).
- Theme: light by default, never the OS setting. `src/lib/theme.ts` holds the per-device choice (`localStorage` `everybird:theme`) and `THEME_SCRIPT`, which `app/layout.tsx` inlines in `<head>` to set `<html data-theme>` before the first paint (`suppressHydrationWarning` on `<html>`). `tokens.css` has no `prefers-color-scheme` rule. Share images follow the current theme.
- eBird files keep their own slots: `Saved.records` is keyed by `Slot` (`model.ts`): `ebird` (MyEBirdData, places down to the county), `ebird-list` (the life list download, state or province only), `inat`, `manual`. Unmatched rows carry `slot` when it differs from `source`; fixes are keyed `unmatchedKey(u)` ("slot:row"). `storage.load()` and `fromJson` migrate lists and backups saved before `ebird-list` existed (`migrateSaved`; load rewrites `everybird:v1` in place). On equal first dates `buildList` keeps the record with the most place detail (sub2 > sub1 > country).
- `src/`: `lib/` (`species/` (`name-search.ts`: the word-prefix, accent-insensitive name matching shared by `species.search`, `suggestBirds` and `Filter.q`), `import/`, `list/`, `layout/`, `share/` (`link.ts`, `convert.ts`, `make-link.ts`, `image.ts`, `og.ts`, `og-server.ts`, `origin.ts`), `analytics.ts`, `download.ts`, `format.ts`, `sticker-url.ts`), `components/` (`app/`, `import/`, `edit/`, `share/`, `filters/` (`FilterBar`: LifeList's one-level-at-a-time filters, a mono rank label and chips with muted counts, the breadcrumb "All birds / Perching birds / Crows" once a parent is chosen, an order with one family ending the breadcrumb with that family; Places (map, Countries) and Time (Years, then Trips) in tabs follow the same pattern; under 600px each level is one "Choose an order 18" button opening `PickerSheet`; `Chip` has no icon), `map/CountryMap.tsx`, `dialog-utils.ts`, `collage/`: `Collage` stage with keyboard and motion, `Bird`, `Tally`, `BirdCard` (LifeList's card, layout C: mass top-right, mono date and place lines), `ListView` (LifeList's rows), `Marks`, `icons.tsx` (the site's glyphs), `collage-motion.ts` style writer, `collage-hit.ts` silhouette hit-testing, `collage.css`), `styles/` (`tokens.css` holds the design tokens, `globals.css` the base styles). The `@/*` alias maps to `./src/*`.
- `tests/`: Vitest unit tests; `tests/fixtures/` are synthetic only.
- `e2e/`: Playwright specs.
- `data/`: hand-kept overrides and synonyms; `data/raw/` is git-ignored. `public/data/`: generated JSON the app loads.
- `scripts/build-data/`, `scripts/validate/`: data build and validation scripts.
- `private/`: Yusuf's real files. Git-ignored. Never read from tests or commit.
- Fonts: Satoshi and Cabinet Grotesk load from Fontshare in `app/layout.tsx`; Geist Mono via `next/font/google`.
