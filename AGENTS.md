# Everybird: agent instructions

Everybird turns any birder's life list into a sticker collage. Import an eBird export or an iNaturalist username, or tick birds by hand; filter, edit and share. The list stays in the browser. It uses Yusuf's personal-site design system, and its collage page mirrors his /lifelist. Pages: Collage `/`, Settings `/settings`, About `/about`, shared view `/s/[token]`. Read these before any work:

- **Design system:** `DESIGN.md` (tokens, type, components, motion, voice, accessibility; sidecar `.impeccable/design.json`, product context in `PRODUCT.md`). Match it, and match `/lifelist`, for any UI work.
- **Spec (approved by Yusuf, 2026-11-05):** `docs/superpowers/specs/2026-11-05-everybird-design.md`, with "Changes after approval" at its end.
- **Plan (25 tasks):** `docs/superpowers/plans/2026-11-05-everybird.md`
- **Validation:** `docs/validation.md` (launch checklist; aggregates only, no personal data).

## Rules

- Keep repository documentation focused on the application’s implementation, build and operation.

- **Never commit personal data.** `private/` holds Yusuf's real eBird exports and his `lifelist.json`, and it's git-ignored. Test fixtures must be synthetic. Never commit coordinates, checklist comments or anything copied from those files.
- **Credit the stickers.** On the site, the footer's "All credits" link (→ /about#credits) and the full credit on About; on share images and link previews, the footer line "everybird.yusuftaleb.com · stickers by huashu" (`FOOTER_LINE` in `image.ts`); in the share text (`navigator.share`), the full credit with the licence and link, "Stickers: huashu-bird-sticker (CC BY 4.0) github.com/alchaincyf/huashu-bird-sticker" (`SHARE_CREDIT`). The license link is https://github.com/alchaincyf/huashu-bird-sticker.
- **Buy Me a Coffee stays quiet.** `COFFEE_URL` appears only as a plain text link in the footer and, on About and in the share dialog, as Buy Me a Coffee's own static button image (self-hosted `public/buy-me-a-coffee.png`, no widget, script or cookies); never on share images or link previews, no pop-ups.
- **Never commit the font files** for Satoshi and Cabinet Grotesk. Load them from Fontshare's CSS.
- **Read-only references** in Yusuf's website repo (`/Users/yusuf/orca/projects/personal_website/framer-site/`): `code-components/LifeList.tsx`, `code-components/PlacesMap.tsx`, `scripts/lifelist/*.py` and `HANDOFF.md` ("Life list v4" to "v7.7"). Don't edit that repo.
- **Ask Yusuf first, every time,** before anything outward-facing: creating GitHub repos, pushing, enabling GitHub Pages, creating or deploying the Vercel project, deploying the Cloudflare Worker (`npm run cf:deploy`), or posting anything. That's plan Task 25.
- **Agents test code only** (Yusuf, 2026-11-15, binding): lint (`npm run lint`), typecheck (`npx next typegen && npx tsc --noEmit`) and unit tests (`npx vitest run <files>` for what changed, one full `npx vitest run --maxWorkers=1` when a task is done). No Playwright/e2e or browser tests, no screenshots, no dev servers for visual checks, no visual or design reviews from screenshots. The e2e specs stay in the repo and are kept up to date with the code (`tsc` type-checks them), but agents don't run them: Yusuf tests the UI and visuals on the Vercel preview (branch previews until the Hobby pause, around 2026-11-18; after that, `npm run cf:preview`).
- **Keep this file current** as commands and structure change.

The sppgroup endpoint has no version (it ignores `version=`), so family groups are the fetch day's; the manifest records a `sha256` per downloaded raw file. Each of the 20 `NAME_LOCALES` sets must have exactly the English taxonomy's species codes; Dutch `nl` is fetched as `nl_NL`, Polish `pl` as `pl` (eBird's near-complete global set, maintained by Sławomir Karpicki-Ignatowski). Raw taxonomy and groups, including English groups for exact family matching, are git-ignored and recorded with fetch dates in `data/raw/manifest.json`. `npx tsx scripts/build-data/build-names.ts` writes `public/data/names.<locale>.v1.json` (`{ v: 1, locale, taxonomy, names, fam }`), regional → base fallbacks baked in, names normalised (NFC, NBSP and runs of whitespace to one space, trimmed), names equal to English in any case omitted (the English reference is the raw `ebird-taxonomy.json`'s `comName` for the published codes; eBird fills a missing pt_BR/pt_PT name with the English one in lower case: about 8,000 of them, so pt covers 3,065 of 11,201 species, es and nl about 11,180, pl 11,197), every locale's names with their first letter capitalised (`capFirst`; the rest, inner Title Case included, as eBird wrote it). A missing raw file stops the build naming `fetch-sources.ts --names-only`. Family labels are sentence case in every language (proper nouns and, in Dutch, proper adjectives keep their capital). The hand-kept family labels in `data/i18n/families.{es,pt,nl,pl}.json` are **LLM translations awaiting fluent-speaker review**, including explicit cognates identical to English; hand labels win, then exact English group matches, except a group equal to the family's scientific name, containing any …idae name or a "(" (`usableGroupName`), else English is omitted and the build warns, listing the families. Hand labels also replace eBird's Title Case groups. There are 146/120/161/91 hand labels respectively (es/pt/nl/pl) for the 250 families in taxonomy 2026; eBird's Polish groups label the other 159 Polish families. `tests/build-names.test.ts` requires every family labelled, labels unique per language, no brackets or scientific names, no capital inside a label outside its `PROPER` allow-list, and at least 200 names of its own in each regional es_XX file.
