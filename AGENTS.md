# Everybird: agent instructions

Everybird turns any birder's life list into a sticker collage. Import an export (eBird, observation.org, iGoTerra, Scythebill, a spreadsheet) or an iNaturalist username, or tick birds by hand; filter, edit and share, as a collage, a list, a map or a tree. The list stays in the browser. It uses Yusuf's personal-site design system, and its collage page mirrors his /lifelist. Pages: My birds `/` (the Collage, List, Map and Tree views), Settings `/settings`, About `/about`, Compare `/compare`, shared view `/s/[token]`, shared comparison `/c/[token]`. Read these before any work:

- **Design system:** `DESIGN.md` (tokens, type, components, motion, voice, accessibility; sidecar `.impeccable/design.json`, product context in `PRODUCT.md`). Match it, and match `/lifelist`, for any UI work.
- **Spec (approved by Yusuf, 2026-11-05):** `docs/superpowers/specs/2026-11-05-everybird-design.md`, with "Changes after approval" at its end.
- **Plan (25 tasks):** `docs/superpowers/plans/2026-11-05-everybird.md`
- **Validation:** `docs/validation.md` (launch checklist; aggregates only, no personal data).

## Rules

- Keep repository documentation focused on the application’s implementation, build and operation.

- **Never commit personal data.** `private/` holds Yusuf's real eBird exports and his `lifelist.json`, and it's git-ignored. Test fixtures must be synthetic. Never commit coordinates, checklist comments or anything copied from those files.
- **Credit the stickers.** On the site, the footer's "All credits" link (→ /about#credits) and the full credit on About; on share images and link previews, the footer line "everybird.yusuftaleb.com · stickers by huashu" (`FOOTER_LINE` in `image.ts`); in the share text (`navigator.share`), the full credit with the licence and link, "Stickers: huashu-bird-sticker (CC BY 4.0) github.com/alchaincyf/huashu-bird-sticker" (`SHARE_CREDIT`). The license link is https://github.com/alchaincyf/huashu-bird-sticker.
- **Buy Me a Coffee stays quiet.** `COFFEE_URL` appears only as a plain text link in the footer and, on About and in the share dialog, as Buy Me a Coffee's own static button image (self-hosted `public/buy-me-a-coffee.png`, no widget, script or cookies); never on share images or link previews, no pop-ups.
- **Never commit the font files** for Satoshi and Cabinet Grotesk. Load them from Fontshare's CSS.
- **Read-only references** in Yusuf's website repo (`/Users/yusuf/orca/projects/personal_website/framer-site/`): `code-components/LifeList.tsx`, `code-components/PlacesMap.tsx`, `scripts/lifelist/*.py` and `HANDOFF.md` ("Life list v4" to "v7.7"). Don't edit that repo.
- **Ask Yusuf first, every time,** before anything outward-facing: creating GitHub repos, pushing, enabling GitHub Pages, creating or deploying the Vercel project, deploying the Cloudflare Worker (`npm run cf:deploy`), or posting anything. That's plan Task 25.
- **Agents test code only** (Yusuf, 2026-11-15, binding): lint (`npm run lint`), typecheck (`npx next typegen && npx tsc --noEmit`) and unit tests (`npx vitest run <files>` for what changed, one full `npx vitest run --maxWorkers=1` when a task is done). No Playwright/e2e or browser tests, no screenshots, no dev servers for visual checks, no visual or design reviews from screenshots. The e2e specs stay in the repo and are kept up to date with the code (`tsc` type-checks them), but agents don't run them: Yusuf tests the UI and visuals on the Vercel preview (branch previews until the Hobby pause, around 2026-11-18; after that, `npm run cf:preview`).
- **Keep this file current** as commands and structure change.

The geometry check scrolls the stage a screen at a time (big lists render only what is near the viewport). About 6–10 minutes.

- Data pipeline (`scripts/build-data/`), in order: `npx tsx scripts/build-data/fetch-sources.ts [--huashu-only | --names-only | --tree-only] [--taxonomy <YYYY|latest>]` (downloads the eBird taxonomy at the pinned year (see Bird names) with its 26 name sets and groups, huashu at the commit `data/huashu.lock.json` pins, Natural Earth and iso-codes into the git-ignored `data/raw/`, writes `data/raw/manifest.json`; `--huashu-only` just moves `data/raw/huashu` to the pinned commit), then `npm run data` = `copy-synonyms` → `build-species` → `build-names` → `build-groups` → `build-geo` → `build-stickers` → `link-index`. Needs `data/raw/` and `../everybird-stickers` (or `STICKERS_OUT`). Then `npx tsx scripts/build-data/check-stickers.ts [--tier 1024]` (decodes every webp with sharp, 1024 files too when present, lists failures and codes missing a screen size; `--tier 1024` also requires the current print file, at its `sv` path, of every `st` species in `public/data/species.v1.json`; prints the `build-stickers` rebuild commands with bare codes; exit 1 if any).
- **Bird names:** `npx tsx scripts/build-data/fetch-sources.ts --names-only` fetches only the pinned eBird taxonomy and name groups (GETs, no key needed; each request 3 tries with backoff and a 60 s timeout, everything held in memory and written only once all have succeeded, so a failure leaves `data/raw` as it was; a full run likewise writes nothing until every download is in), leaving huashu and geographic sources alone; it also overwrites `data/raw/ebird-taxonomy.json` (the English taxonomy build-species reads) with the pinned year's. The year (`pinnedTaxonomy`) is the committed `public/data/species.v1.json`'s `ebirdTaxonomy` first, then `data/raw/manifest.json`'s, never silently the latest; full source fetches use the same pin. `--taxonomy <YYYY|latest>` (either mode; `--taxonomy=<x>` is refused) picks another year: the yearly upgrade is `fetch-sources.ts --taxonomy latest`, then `npm run data` (build-species then build-names), so species and names move together; build-names refuses a manifest year that differs from species.v1.json's and names the flag. The sppgroup endpoint has no version (it ignores `version=`), so family groups are the fetch day's; the manifest records a `sha256` per downloaded raw file. Each of the 26 `NAME_LOCALES` sets must have exactly the English taxonomy's species codes; Dutch `nl` is fetched as `nl_NL`, Polish `pl` as `pl` (eBird's near-complete global set, maintained by Sławomir Karpicki-Ignatowski), French `fr_FR` (France's names, the French base) and `fr` (eBird's plain French, North American usage, for Canada; eBird has no `fr_BE` or `fr_CH`, both return `fr`) German `de` (one set: `de_AT` and `de_CH` return it), Italian `it`, Swedish `sv` and Danish `da`. Raw taxonomy and groups, including English groups for exact family matching, are git-ignored and recorded with fetch dates in `data/raw/manifest.json`. `npx tsx scripts/build-data/build-names.ts` writes `public/data/names.<locale>.v1.json` (`{ v: 1, locale, taxonomy, names, fam }`), regional → base fallbacks baked in, names normalised (NFC, NBSP and runs of whitespace to one space, trimmed), names equal to English in any case omitted (the English reference is the raw `ebird-taxonomy.json`'s `comName` for the published codes; eBird fills a missing pt_BR/pt_PT name with the English one in lower case: about 8,000 of them, so pt covers 3,065 of 11,201 species, es and nl about 11,180, pl 11,197), every locale's names with their first letter capitalised (`capFirst`; the rest, inner Title Case included, as eBird wrote it). Each name is eBird's first; for the sets in `IOC_COLUMNS` (`it`, `sv`, `da`), where eBird only repeats the English name, the IOC World Bird List v15.2 name (Gill, Donsker & Rasmussen, CC BY 3.0) from huashu's `data/names.csv` at the pinned commit, through build-species' crosswalk (`iocNames`: the species' own huashu record, never a form); English last (left out of the file). Italian gets most of its names this way (eBird's `it` has few of its own); About's taxonomy credit names IOC in those three languages. A missing raw file stops the build naming `fetch-sources.ts --names-only`. Family labels are sentence case in every language (proper nouns and, in Dutch, proper adjectives keep their capital; German keeps every noun's). The hand-kept family labels in `data/i18n/families.{es,pt,nl,pl,fr,de,it,sv,da}.json` are **LLM translations awaiting fluent-speaker review**, including explicit cognates identical to English; hand labels win, then exact English group matches, except a group equal to the family's scientific name, containing any …idae name or a "(" (`usableGroupName`), else English is omitted and the build warns, listing the families. Hand labels also replace eBird's Title Case groups. There are 146/120/161/91/105/95/250/89/120 hand labels respectively (es/pt/nl/pl/fr/de/it/sv/da) for the 250 families in taxonomy 2026; eBird's Polish groups label the other 159 Polish families, and eBird has no Italian groups. `tests/build-names.test.ts` requires every family labelled, labels unique per language, no brackets or scientific names, no capital inside a label outside its `PROPER` allow-list, and at least 200 names of its own in each regional es_XX file. Rerun `data-files.ts` after rebuilding names. The huashu sync leaves names files alone; new codes fall back to English. Uploading hashed names with `upload-stickers-r2.ts --data` is an outward step for the orchestrator after Opus review and approval, before deployment. Note the huashu-sync workflow runs `upload-stickers-r2.ts --data` on every run with changes, and it uploads every hashed data file missing from the bucket (names included), so once the names files are on the default branch its next run with changes publishes them even if nobody uploaded by hand.

## Smart search groundwork (item 9, A and C)

- `npx tsx scripts/build-data/build-groups.ts` GETs eBird species groups for every language eBird has them in (`GROUP_LOCALES`: en, es, pt_BR, nl, pl, fr, de, sv, da, ru, zh_SIM, zh; none for Italian or Japanese) (public endpoint; optional `EBIRD_API_KEY` stays in the header), validates localized bounds against the committed species taxonomy, and writes `public/data/groups.v1.json` (`{v:1,taxonomy,groups:[{id,name:{en,es,pt,nl,pl,fr,de,sv,da},lo,hi}]}`; inclusive bounds). Included in `npm run data`. Rerun `data-files.ts` after rebuilding. Never upload until review and Yusuf's approval. Group IDs are English-name slugs; `data/i18n/group-synonyms.json` maps everyday words to these groups (broad aliases such as raptors/warblers/sparrows select the named eBird group, not every family that might be called that).
- Saved v5 adds optional `SourceRecord.seenMonths` and `Unmatched.seenMonths`: one string per place, `<months>|region[|county]`, where `<months>` packs one five-character chunk per year (year as three base-36 digits, the 12-bit month mask as two base-64 digits, bit 0 = January; years ascending), written by `SeenAgg.getMonths`. The earlier `YYYY-MM,YYYY-MM|region` shape still decodes. MyEBirdData and iNaturalist fill it; fixed unmatched rows retain it. `decodeSeenMonths` decodes it. Migration does not synthesize month history for v1–v4; absent is legacy/life-list-only, `[]` means a full source had no dated, located sighting. Existing `buildSeen` and filtering still use earliest dates; part B must consume the month sets and implement the fallback.
- `src/lib/search/smart.ts`: pure `parseSmart(q, ctx)` and `withoutChip(q, chip)`. `SmartFilter = Partial<Filter & SmartFilterFields>` adds only a type contract for group/basis/statuses, no filter behavior. Context takes the clock, the UI language (`SearchLang` = `Lang`), group rows, regions, list place keys, optional localized status labels, and optional on-list species/order/family labels. Dates emit inclusive YYYY-MM; last N months means N calendar months including this month. Quotes force name text. Scalar dates/group/taxonomy take the first recognized match; status/place sets union. Chips carry exact source offsets and tokens; reparse after editing or removing one. Remaining words retain their spelling and punctuation.
- `src/lib/places/names.ts` is the single home for the shared collision-safe country map, sub1 index, and observation.org alias tables (re-exported by `src/lib/import/sub1-index.ts` and `src/lib/import/obsorg-places.ts`), plus country abbreviations and Portuguese Intl names.
- Part D (DockSearch, done): the query's group, place, period, Red List status and "lifers" show as "Understood as" chips (`ChipRow`, the filter's chip; order and family words stay bird-name hits, as before). Enter, or "Show these birds" (both only when chips show; a highlighted hit wins over Enter), applies them in one `{type:'filter'}` through `applySmart` (`src/lib/search/apply.ts`): a search replaces every filter: `applySmart` starts from nothing and sets the kinds the shown chips hold (places as one dimension, through `withPlaces`), so no earlier filter, order or family included, stacks on it. Typing applies nothing. Name hits search the query as typed, or, with chips and no hit, what the chips leave over (`nameQuery`). `groups.v1.json` loads once when the search opens (`fetchData`; a failure is not cached). With no per-place months on the user's own list (`hasMonths`), a dates chip shows `ui.search.note`. Strings: `ui.search` in all four languages. Part B (`group` and `basis` matching, the Time switch, the card's first sighting inside a filter) is in too (see the filter model above).
